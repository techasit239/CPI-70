# ระบบติดตามการสำรวจค่าเช่าบ้าน สนค.

เว็บแสดงผลจาก Google Sheets สองหน้า: แผนที่ 77 จังหวัดพร้อมยอดภาคสนาม 4,200 / ติดตามฐานเดิม 4,900 และปฏิทินลงพื้นที่พร้อมกำหนดส่งหลังเสร็จจริง 7 วัน ไม่มีการเพิ่ม แก้ หรือลบข้อมูลบนเว็บ

สถานะรุ่นนี้: โครงสร้างพร้อมเชื่อมต่อ แต่ชีตที่ผู้ใช้ให้มายังว่างและยังไม่ได้ตรวจการเข้าถึง CSV จริง จึงไม่แสดงข้อมูลตัวอย่างหรืออ้างว่าเชื่อม Zoho แล้ว วันเริ่มสัญญาและรายชื่อพื้นที่ 56 จังหวัดยังต้องยืนยัน

## เปิดเว็บ

GitHub → Settings → Pages → Deploy from a branch → main → /(root) → Save ใช้ `index.html` เป็นหน้าแรก ส่วน `code_artifact.html` ส่งต่อมายังหน้าเดียวกัน ไม่ต้องติดตั้งหรือ build

คาดหวัง URL หลังเจ้าของเปิด Pages: https://techasit239.github.io/CPI-70/ (ต้องตรวจ deployment ก่อนแจ้งว่าออนไลน์แล้ว) ใช้ path แบบ relative รองรับ project subdirectory ไม่มี SPA rewrite

ทดสอบในเครื่องผ่าน HTTP server เช่น `python -m http.server 8000` ในโฟลเดอร์นี้ แล้วเปิด http://localhost:8000/ อย่าเปิดแบบ file:// เพราะเบราว์เซอร์จะจำกัด fetch และ ES modules

## ตั้งค่า Google Sheets ครั้งแรก

ชีตงาน: https://docs.google.com/spreadsheets/d/1dz-enEv9mYElM8lwGatv9lhiGNrummQeF5em-dK0Qhc/edit

1. สร้างแท็บ `Assignments` และ `Surveys` นำเข้าหัวคอลัมน์จาก `templates/assignments.csv` และ `templates/surveys.csv` อาจแยก Surveys ตามทีมได้โดยทุกแท็บใช้หัวเดียวกัน
2. ตั้งคอลัมน์วันที่เป็น plain text รูปแบบ ค.ศ. `YYYY-MM-DD` เช่น `2026-11-02` ตั้งรหัสแบบสอบถามและ group_id เป็น plain text เพื่อรักษาเลขศูนย์นำหน้า
3. เผยแพร่เฉพาะแท็บที่ไม่มีข้อมูลส่วนบุคคลผ่าน File → Share → Publish to web เลือก CSV หรือใช้ลิงก์ export CSV ของชีตที่เปิดให้อ่านโดยไม่ต้องล็อกอิน ทดสอบลิงก์ด้วยหน้าต่างไม่ระบุตัวตนว่าคืน CSV จริง ไม่ใช่หน้า login/HTML
4. ใส่ URL CSV แผนงานใน `config.json` → `assignmentsCsvUrl` และ URL แบบสอบถามทุกแท็บใน `surveyCsvUrls` ไม่ใช้ URL `/edit` สำหรับ fetch ตัวอย่างโครงลิงก์: `https://docs.google.com/spreadsheets/d/SHEET_ID/export?format=csv&gid=TAB_GID` ต้องนำ TAB_GID จากแท็บจริง ห้ามเดาว่าเป็น 0
5. ตั้ง `monthOne.startDate`, `monthOne.endDate` และ `monthOne.groupIds` เป็น `["4200"]` เพื่อติดตามภาคสนาม 600 ชุด ตามคำขอ หรือ `["4900"]` สำหรับฐานเดิม ช่วงวันที่ต้องตรงวันตัดรอบตามสัญญา ไม่เดาจากวันที่สร้าง repo หากยังไม่ตั้ง ให้เว้นทั้งสามค่าเหมือนค่าเริ่มต้น
6. หลังตั้งค่าการเชื่อมต่อครั้งแรก ข้อมูลทีม จังหวัด วันลงพื้นที่ และแบบสอบถามแก้ที่ Google Sheets เท่านั้น ทุกคนและทุกการรีเฟรชอ่านจากต้นทางเดิม

ไม่ฝัง API key, OAuth token หรือ Zoho secret ใน repo/HTML ชีตที่เผยแพร่ CSV ถือว่าเปิดอ่านได้ การนำข้อมูลส่วนบุคคล ที่อยู่ละเอียด GPS ชื่อผู้ตอบ หรือหลักฐานรูปเข้าแท็บนี้จะทำให้บุคคลทั่วไปดาวน์โหลดได้ ถ้าต้องใช้ชีตส่วนตัว ต้องเพิ่ม backend ที่ตรวจสิทธิ์ก่อน เว็บ static รุ่นนี้ไม่รองรับ private Sheets

## แท็บ Assignments

| คอลัมน์ | ความหมาย |
| --- | --- |
| team | ชื่อทีมจริง ไม่ใช้ชื่อผู้ตอบ |
| province | ชื่อจังหวัดไทยเต็มตาม provinces.json เช่น กรุงเทพมหานคร |
| start_date | วันเริ่มลงพื้นที่ตามแผน |
| end_date | วันสิ้นสุดตามแผน |
| completed_date | วันเสร็จจริง เว้นว่างได้หากยังไม่เสร็จ |
| color | สีทีมแบบ #RRGGBB ทีมเดียวกันต้องใช้สีเดียวกัน |

หนึ่งแถวต่อทีม × จังหวัด × รอบการลงพื้นที่ รองรับหลายทีมในจังหวัดเดียวกัน โดยแผนที่ใช้สีม่วงและรายละเอียดแสดงทุกทีม กำหนดส่งจริง = completed_date + 7 วันปฏิทิน ถ้ายังไม่มีวันเสร็จจริงจะแสดง end_date + 7 เป็น **คาดการณ์** ไม่รายงานว่าเสร็จหรือส่งแล้ว

## แท็บ Surveys และการเชื่อม Zoho

| คอลัมน์ | ความหมาย |
| --- | --- |
| response_id | รหัสคำตอบถาวรจาก Zoho ไม่ใช้หมายเลขแถว ถ้าติดตามบ้านเดิมหลายรอบต้องมีรหัสคำตอบใหม่แต่ละรอบ |
| team | ชื่อทีมที่ตรง Assignments |
| province | จังหวัดที่ตรง Assignments |
| group_id | `4200` = ภาคสนาม, `4900` = ติดตามฐานเดิม |
| type | ประเภทบ้านตาม TOR: บ้านเดี่ยว, ห้องชุด, ทาวน์เฮ้าส์/ทาวน์โฮม/บ้านแฝด, เรือนแถว/ห้องแบ่งเช่า, ตึกแถว/อาคารพาณิชย์ |
| collected_date | วันที่เก็บ ค.ศ. YYYY-MM-DD ไม่ใช่วันที่เปิดหน้าเว็บ |

Zoho → Google Sheets ต้องตั้งค่าการส่งข้อมูลและแปลงคอลัมน์ให้ตรง schema นี้ในฝั่ง Zoho / ระบบเชื่อมต่อก่อน เว็บอ่านชีตเท่านั้น ไม่ส่งข้อมูลกลับและไม่สร้างการเชื่อม Zoho ให้เอง หลีกเลี่ยงการนำ raw responses ที่มีข้อมูลส่วนบุคคลมา Publish โดยตรง สร้างแท็บสำหรับแสดงผลแยกต่างหาก

ยอดเป็นจำนวนคำตอบในชีต ยังไม่ใช่ยอดรับรองคุณภาพ หากต้องการยอดผ่านตรวจให้ source ส่งเฉพาะคำตอบที่ผ่านตรวจ ระเบียนซ้ำ group_id + response_id ข้ามแท็บที่ข้อมูลเหมือนกันจะนับหนึ่งครั้ง ถ้าข้อมูลขัดแย้งจะหยุดรับชุดใหม่พร้อมแจ้งข้อผิดพลาด รหัสเดียวกันคนละกลุ่มถือว่าคนละคำตอบ ไม่แสดงยอดรวม 9,100 เป็นจำนวนบ้านไม่ซ้ำ

อ่านใหม่อัตโนมัติทุก 60 วินาที ปรับได้ 30–3,600 วินาทีใน config แต่ Google Published CSV และ Zoho อาจมีความหน่วง จึงไม่ใช่ push realtime การดึงแต่ละครั้งมี timeout 20 วินาทีและไม่ทำงานซ้อน ข้อมูลทุกชีตต้องผ่านตรวจทั้งหมดก่อนเปลี่ยนหน้าจอ หากแท็บใดล้มเหลวคงข้อมูลชุดเดิมพร้อมข้อความล้าสมัยและเวลาอ่านสำเร็จ ไม่มีการแสดงศูนย์หรือ demo แทนความล้มเหลว ชีตมีหัวครบแต่ยังไม่มีแถวถือเป็นยอดศูนย์จริง

## หลักฐานเป้าหมายและสิ่งที่รอยืนยัน

ตรวจ TOR.pdf ต้นฉบับในโฟลเดอร์งาน หน้า 5–7: ภาคสนามรวม 4,200 ฐานเดิมรวม 4,900 พื้นที่ 56 จังหวัดใน 5 ภูมิภาค ข้อ 4.3.1 และ 4.3.2 บนหน้า 5 ระบุเดือนละไม่น้อยกว่า 600 ข้อมูลทั้งสองส่วน ข้อความสรุปเดิมบางไฟล์ที่ระบุภาคสนาม 500 ต้องแก้ให้ตรงต้นฉบับ

ตาราง 695 / 765 / 1,377 / 757 / 606 รวม 4,200 มาจากแผนเบื้องต้นในแชต “จัดทำข้อเสนอเทคนิคจาก TOR” ผู้ใช้เลือกฐานประชากรทั้งประเทศ ยังไม่ใช่โควตา 56 จังหวัดที่อนุมัติ ไม่สร้างรายชื่อจังหวัดหรือวันที่ปลอมในชีต ต้องยืนยันรายชื่อจังหวัด ทีมจริง วันลงนาม และวันตัดรอบก่อนเปิดใช้งานจริง

## การทดสอบและข้อจำกัด

ใช้ Node 22+ รัน `npm test` ไม่ต้องลง dependencies การทดสอบ 11 กรณีครอบคลุม CSV ที่มี comma/quote/ขึ้นบรรทัดใหม่, schema, วันที่, deadline, IDs ซ้ำ, TOR filter, ต้นทางล้มเหลว และรายชื่อ 77 จังหวัด ผ่านแล้ว รวมถึงตรวจด้วย headless Chrome บน desktop/mobile: โหลดชีตจำลอง, ข้อความ XSS ไม่กลายเป็น HTML, วันส่ง +7, สลับเดือน, คงยอดเก่าเมื่อ HTTP 403, รีเฟรชอ่านยอดใหม่ และทดสอบ CDN/GeoJSON จริงว่ามี polygon 77 จังหวัดและคลิกดูจังหวัดได้ การทดสอบชีตใช้ข้อมูลจำลองเฉพาะในเครื่อง ไม่ได้ใส่ในหน้าใช้งานจริง

แผนที่ใช้ Leaflet 1.9.4 พร้อม SRI, OpenStreetMap tiles และขอบเขตจาก apisit/thailand.json ปัก commit `2c698dfab258ce534cd541a846f94e08c681d1a2` ที่ตรวจว่ามี 77 จังหวัดจริง หากโหลดขอบเขตไม่ได้จะใช้ dropdown จังหวัด ไม่สร้าง polygon ปลอม การเรียกภายนอกต้องมีอินเทอร์เน็ตและควรยืนยันสิทธิ์ใช้ข้อมูลขอบเขตสำหรับการเผยแพร่ของหน่วยงานก่อนเปิดจริง เพราะ repo ต้นทางไม่แสดง license ชัดเจน

หน้าจอใช้ textContent / DOM nodes แสดงข้อความชีต ไม่มี innerHTML, eval หรือ inline handlers ไม่ export CSV จากหน้าเว็บ จึงตัดช่องทาง HTML injection และ CSV formula injection ของระบบเดิม CSP ใน meta เป็นมาตรการเสริม (GitHub Pages ตั้ง HTTP response headers แบบกำหนดเองไม่ได้) ยังต้องคุมสิทธิ์แก้ไขชีตและตรวจแหล่งข้อมูล
